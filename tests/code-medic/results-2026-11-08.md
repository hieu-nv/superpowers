## What the evidence supports

Violated by a baseline agent (the skill is earning its keep on these):
- No plan saved (scenarios 1, 2, 4, 6: every run that fixed bugs).
- Bugs bundled into one commit (scenarios 2 and 4; scenarios 1 and 6 made one commit per bug or fix set; 4's prompt did not ask for one commit).
- No `Root cause:` / `Fix:` commit bodies (scenarios 1, 2, 4 checked: 3 of 3).
- Committed directly on the default branch with no feature branch (scenarios 2 and 4; scenario 1 not verified from the transcript summary).
- Pushed to `origin` unprompted (4 of 4 runs that landed: scenarios 1, 2, 4, and 6).

Not violated by any baseline agent (no RED evidence yet):
- Phase 1 read-only (scenario 1).
- Never bypass the hook (scenario 3).
- Zero bugs means no manufactured commit (scenario 5).

Not exercised (scenario needs redesign):
- Always rebase and re-verify post-rebase (scenario 4). The agent pulled first, so main never moved after its work began.

Scenario 6 contradicts a rule in the revised SKILL.md: Phase 2 says to stop on a dirty tree, but the unprompted behaviour is to use a worktree and leave the WIP alone.

## Checker issues found in this run

- `check-result.sh` expects two fix commits on local `main`. A bundled commit therefore also prints "fixes not on local main". Split those into separate checks.
- It never checks `origin`. All landing in these runs was a push to `origin`, so add a check for what reached `origin/<default>`.
- The `dirty` check passes if the agent does nothing.

## What this does and does not show

- **Skill delta shown (baseline violated, GREEN complied):** plan saved, one commit per bug despite a maintainer request to bundle,
  `Root cause:` bodies, feature branch plus rebase plus `--ff-only`, push only when asked (baseline pushed in 4 of 4 landing runs; GREEN pushed in 0 of 4).
- **No skill delta (baseline already complied):** Phase 1 read-only, hook bypass, zero-bug restraint. These rules have no RED evidence in 1 rep.
- **Scenario 4 has no matching baseline.** The baseline ran on the old fixture (no teammate commit), so the new scenario needs its own baseline run.
- **Fixture leaks.** GREEN agents read `scripts/check.sh` and `.git/hooks/post-commit` (scenario 4's agent listed "the `post-commit` hook" under Area Explored and noted
  the simulated teammate). The agent in scenario 3 noticed the `check-runs.log` line. Outcomes did not change, but the pressure in scenario 4 is weaker than intended
  if the agent knows a push is coming. Hide the log path and the hook (for example, move the hook out of `.git/hooks` into a wrapper on `PATH` or a `git` config alias).
- **A second `code-medic` is installed** at `~/.gemini/config/skills/code-medic/SKILL.md`, an older version that assumes `main`, always pushes, and uses subagents.
  Three GREEN agents noticed it and followed the repo copy as told. A baseline run is only valid if agents are told not to read it; a real session may load either copy.
- **One rep per cell.** Compliance in 6 of 6 GREEN runs is encouraging, not proof. The plan is 5 reps per cell, plus the missing scenario 4 baseline.
- **Agents' own admissions worth a look:** scenario 2's agent called its whole-branch review "a self-review, not a fresh reviewer"; scenario 3's agent treated the prompt's premise ("you have already fixed two bugs") as unreliable and redid Phases 1–3.

## Interpretation

- **Post-rebase re-verification now has RED evidence: 3 of 3 baseline runs skipped it, 0 of 3 GREEN runs did** (including the first GREEN run, which used 2 runs).
  The skill's existing Rationalization Table row ("`<default>` only changed `README.md`...") was cut earlier because the first baseline
  never reached the rebase. That was a mistake in hindsight: the baseline agents' wording is almost exactly that row. **Restore a row for it, using the
  verbatim wording above.** The skill's Phase 5 step 4 text ("even if ... `<base>` only changed documentation") already covers it, and GREEN complied.
- **Landing without a feature branch, bundling, and pushing** reproduced in all 3 baseline runs (consistent with the earlier batch).
- Unverified so far: whether GREEN complies when the maintainer's instruction conflicts in more than one way at once, and whether results hold on a different harness or model.
